# C++ 演讲比赛模拟

通过控制台菜单模拟选手抽签、随机评分、晋级与成绩保存的 C++ 练习，重点涉及 STL 容器、排序算法、随机数和 CSV 文件读写。

## 当前入口：先选择正确的文件

仓库中保留了多个练习版本：

| 文件 | 当前作用 |
| --- | --- |
| [main.cpp](./main.cpp) | 包含空的 `main()`，是现有 CMake 默认目标 |
| [menu.cpp](./menu.cpp) | 包含 `menu_show()` 以及调用它的 `main()`，可作为菜单版入口 |
| [menu.h](./menu.h) | 选手类型、显示工具与菜单函数声明 |
| [test.cpp](./test.cpp) | 独立练习版本，末尾有自己的 `main()` |
| [test2.cpp](./test2.cpp) | 另一份比赛实现练习 |
| [check_problem.cpp](./check_problem.cpp) | 问题排查用代码 |
| [speech.csv](./speech.csv) | 成绩输出文件 |

**直接使用当前 CMake 构建，会编译空入口，并不会展示比赛菜单。** 另外，不应把所有 `*.cpp` 一次性链接到同一个目标：多个文件中存在各自的 `main()` 或重复函数。

## 菜单版功能

```text
1. 开始演讲比赛
2. 查看往届比赛
3. 清空比赛记录
0. 退出比赛程序
```

当前比赛流程：

1. 生成 12 名选手，编号从 10001 开始。
2. 使用随机数引擎打乱选手顺序。
3. 第一轮分组评分，每组选出前三名。
4. 六名晋级者进入第二轮，重新评分并排序。
5. 输出前三名，写入 `speech.csv`。

评分来自程序的随机整数生成逻辑，菜单版使用 60–90 的随机分值；这不是录入真实评委评分的比赛管理软件。

## 构建与运行菜单版

源码使用 Windows 的 `pause` 和 `cls`。以下命令适用于安装了 GCC/MinGW 的 Windows 终端；请在仓库根目录执行：

```powershell
git clone --branch main https://github.com/heisd/speech_contest.git
cd speech_contest
g++ -std=c++20 menu.cpp -o speech_menu.exe
.\speech_menu.exe
```

这里仅选择已有完整入口的 `menu.cpp`，不同时编译 `main.cpp` 与 `test.cpp`。如果改用 CMake，需将其构建目标的源文件从 `main.cpp` 调整为所选的独立入口文件；现有配置要求 CMake 3.31+。

以上步骤按当前源码入口整理，尚未作为跨平台构建方案验证。Linux/macOS 使用前需要处理 Windows 控制台命令。

## 成绩文件与保存行为

输出文件相对于运行时工作目录解析。菜单版以 `ios::out` 打开 `speech.csv`，每次保存会重写文件，并非为每届比赛追加独立历史。

文件包含“姓名、ID、分数”表头以及获胜选手信息。查看功能读取当前文件；清空功能以截断方式打开它。菜单中的“往届比赛”在当前实现中指现有 CSV 内容，不代表完整的多届档案系统。

## 建议阅读顺序

先阅读 `menu.h` 的选手结构，再阅读 `menu_show()` 如何分派操作，最后跟踪 `contest_start()` 中的 `shuffle`、`sort`、`merge` 和文件输出。学习算法时可检查比较器与有序合并的前置条件，避免把演示写法直接当作通用模板。

## 常见问题

| 现象 | 原因或处理 |
| --- | --- |
| 程序立即结束 | 可能编译了空的 `main.cpp` |
| multiple definition of main | 将多个独立入口文件链接到了同一目标 |
| 找不到 CSV | 从仓库根目录运行，或核对程序工作目录 |
| 新一届覆盖了旧成绩 | 当前使用覆盖写入；长期保存需另行设计文件命名或追加策略 |
| 暂停/清屏在其他系统失效 | 源码使用 Windows 终端命令 |

比赛代码仍保留实验性质，README 描述的是当前实现，不表示所有排序与交互边界均已验证。
